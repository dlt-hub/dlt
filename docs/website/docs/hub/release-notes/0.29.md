# Release highlights: 0.29

Released September 24, 2026, with `dlthub-client` 0.28.5. This release brings agent jobs into the app with a full trace of what each agent did, moves the jobs list onto the server, adds alerts for successful runs, and makes workspace API keys generally available.

## Agent jobs

[Background agents](../agents/index.md) now have a home in the app. The **Agents** section lists your agent jobs, with run and batch actions and an **investigates** column showing which pipeline each agent looks after, as the [job inspector](../agents/job-inspector.md) does. Search, filters, sorting and paging run on the server, so every agent job is reachable rather than only the page in front of you.

![The dltHub Agents overview, listing agent jobs with run and batch actions and an investigates column naming the pipeline each agent looks after.](https://storage.googleapis.com/dlt-blog-images/dlthub-release-0-29-agent-jobs-list.png)

Open an agent job to browse its runs, and open a run to read its **Summary**, what the agent returned, beside its **Trace**, the structured record of how it got there: the model, the resolved inputs, the tools it was wired with, the per-turn calls and the token counts. The run **Logs** sit alongside both. See [Read the agent run result](../agents/index.md#read-the-agent-run-result) for what each one answers.

![An agent run detail page in dltHub, with the agent's summary beside a trace showing the model, inputs, tools, per-turn calls and token counts, next to the run logs.](https://storage.googleapis.com/dlt-blog-images/dlthub-release-0-29-agent-run-trace.png)

`dlt runtime` knows about agent jobs too, and the jobs list can filter agent jobs in or out.

:::info
Background agents are in private preview.
:::

## Agent runs on a pipeline run

A pipeline job run's detail page now shows the agent runs that run triggered, so a failure and the agent's read of it sit in one place.

![A pipeline job run detail page in dltHub, listing the agent runs that the run triggered.](https://storage.googleapis.com/dlt-blog-images/dlthub-release-0-29-pipeline-run-agent-runs.png)

Each run of a pipeline [job](../pipeline-operations/overview.md) also gets its own dedicated page in this release.

## A faster jobs list

Filtering, sorting and paging on the jobs list now happen on the server, with new filters for last run status, trigger kind, tags and time window. You can pause and resume a job straight from the list.

![The dltHub jobs list with server-side filters applied for last run status, trigger kind and tags, and the row action for pausing a job.](https://storage.googleapis.com/dlt-blog-images/dlthub-release-0-29-jobs-list-filters.png)

The selected tab, run filters and sort order are kept in the URL, so the view you are looking at is the view you share.

## Alerts on success

Alerts are no longer only about failure. You can be notified when a job succeeds, configured from the web app. See [Email notifications](../notifications/email.md#dlthub-platform-alerts).

![The alert configuration in dltHub, with the option to be notified when a job succeeds.](https://storage.googleapis.com/dlt-blog-images/dlthub-release-0-29-success-alerts.png)

Notification emails are also safer: content you supply can no longer inject HTML into them.

## A redesigned datasets overview

The [datasets](../data-discovery/datasets.md) overview page has been redesigned.

![The redesigned datasets overview page in dltHub.](https://storage.googleapis.com/dlt-blog-images/dlthub-release-0-29-datasets-overview.png)

## Workspace API keys are generally available

Workspace API keys are out from behind their feature flag and available to everyone.

[Archived workspaces](../pipeline-operations/what-is-a-workspace.md) are read-only in the UI as well as on the server: actions that would change data are disabled.

## Smaller improvements

- Interactive apps such as Streamlit, marimo and MCP show a self-reloading "Starting your app" page while they boot, instead of a 502.
- The job detail page's Rows Loaded stat reports the most recent run rather than a sum over the last 50.
- The separate Jobs nav item is hidden when the new pipeline job pages are enabled, since Pipelines already leads there.
- Job result payloads from runs are ingested instead of dropped.
- Unsaved variable rows stay in place when their scope changes.
- Table cells keep their state across live refreshes.
- Misrouted workspace pages redirect immediately instead of flashing the wrong page.
- Organization plan limits are bounded, and errors while saving them are shown.

## For API consumers

List responses now carry a `next_cursor` for gap-free scrolling through long lists. `offset` still works, so existing callers are unaffected.
