# Release highlights: 1.22

## Breaking changes

- **Pydantic v1 support removed.** dlt now requires Pydantic v2 and has removed all Pydantic v1 compatibility code. Pipelines pinned to Pydantic v1 or using v1-only APIs like `.dict()`, `@validator`, `parse_obj`, or `orm_mode` must migrate to Pydantic v2. See [#3572](https://github.com/dlt-hub/dlt/pull/3572).
- **`data_type` contract semantic change.** The `data_type` schema contract now applies to full type changes on existing columns, including precision, scale, and nullability, not only to new variant columns. Pipelines using `data_type: freeze` that changed nullable, precision, or scale on existing columns will now be blocked. See [#3572](https://github.com/dlt-hub/dlt/pull/3572).
- **Compound key hints replace instead of merging.** `merge_columns` is no longer purely additive. Redefining a compound hint like `merge_key` or `primary_key` on an already extracted resource now replaces the previous set, so columns dropped from the key correctly lose the hint instead of retaining stale values. See [#3431](https://github.com/dlt-hub/dlt/pull/3431).

## Pydantic data validation overhaul

dlt now requires Pydantic v2 and reworks how models validate data. A `RootModel` discriminated union lets a single resource validate an event stream and dispatch each item to a per-type table, resolved by a discriminator field without re-validating. Schema contracts are now fully enforced on Pydantic model and Arrow items.

```py
from typing import ClassVar, Literal, Union
from typing_extensions import Annotated
from pydantic import BaseModel, Field, RootModel

import dlt
from dlt.common.libs.pydantic import DltConfig


class ClickEvent(BaseModel):
    kind: Literal["click"]
    id: int
    element_id: str


class PurchaseEvent(BaseModel):
    kind: Literal["purchase"]
    id: int
    amount: float


EventUnion = Annotated[Union[ClickEvent, PurchaseEvent], Field(discriminator="kind")]


class Event(RootModel[EventUnion]):
    dlt_config: ClassVar[DltConfig] = {"is_authoritative_model": True}


TABLE_MAP = {"click": "click_events", "purchase": "purchase_events"}
events = [
    {"kind": "click", "id": 1, "element_id": "btn-1"},
    {"kind": "purchase", "id": 2, "amount": 9.99},
]


@dlt.resource(name="events", columns=Event, schema_contract={"data_type": "discard_row"})
def event_stream():
    for item in events:
        yield dlt.mark.with_table_name(item, TABLE_MAP[str(item["kind"])])
```

See [#3572](https://github.com/dlt-hub/dlt/pull/3572).

## Parallel fetching for `rest_api` dependent resources

Dependent resources (transformers) fetch child data for each parent item sequentially by default. Set `parallelized` to `True` on a dependent resource to run those child fetches concurrently in dlt's thread pool. All pages of child data for one parent are collected in memory before yielding, so memory use grows for parents with many child pages.

```py
from dlt.sources.rest_api import rest_api_source, RESTAPIConfig

config: RESTAPIConfig = {
    "client": {"base_url": "https://api.example.com"},
    "resources": [
        "posts",
        {
            "name": "post_comments",
            "parallelized": True,
            "endpoint": {"path": "posts/{resources.posts.id}/comments"},
        },
    ],
}

source = rest_api_source(config)
```

See [#3574](https://github.com/dlt-hub/dlt/pull/3574).

## Atomic table swap for Snowflake replace

The `staging-optimized` replace strategy on Snowflake can now swap the destination and staging tables with `ALTER TABLE ... SWAP WITH` instead of cloning. Set `enable_atomic_swap` to replace data without table downtime. Each table keeps its permissions after the swap, and dlt does not drop the old table, so the previous production table becomes the next load's staging table.

```toml
[destination.snowflake]
enable_atomic_swap = true
```

See [#3540](https://github.com/dlt-hub/dlt/pull/3540).

## Filter dataset relations by load ID

You can now read only the rows from specific loads. Pass `load_ids` to `dataset.table()` or call `.from_loads()` on a relation. For nested tables, dlt joins back to the root table to resolve `_dlt_load_id`. New `dataset.load_ids()` and `dataset.latest_load_id()` list the available loads. This feature is experimental.

```py
import dlt

dataset = dlt.pipeline("my_pipeline", destination="duckdb").dataset()

# list loads and read only the latest one
load_ids = dataset.load_ids()
latest = dataset.table("users", load_ids=load_ids[-1:])
df = latest.df()
```

See [#3547](https://github.com/dlt-hub/dlt/pull/3547).

## Markdown docs and an `llms.txt` index

The docs site now publishes a clean Markdown version of every page, reachable through a new "View Markdown" link, plus an `llms.txt` index of all pages following the llms.txt specification. This makes dlt's documentation easier to feed to LLMs and coding agents.

See [#3635](https://github.com/dlt-hub/dlt/pull/3635).
