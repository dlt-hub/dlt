# Release highlights: 1.22

## Breaking changes

- **Pydantic v1 support removed.** All Pydantic v1 compatibility code has been removed and dlt now requires Pydantic v2. Upgrade any models still written for v1 before updating. See #3572.
- **`data_type` contract now covers full type.** The `data_type` schema contract now applies to the full data type, including precision, scale, and nullability, not only variant (data type change) columns. Pipelines using `data_type: freeze` that changed `nullable`, `precision`, or `scale` on existing columns will now be blocked. See #3572.
- **`merge_columns` removes compound properties.** `merge_columns` was previously additive, which could leave stale compound properties such as `merge_key` in place. It now removes compound properties that should be removed, so merged schemas correctly reflect the latest hints. See #3431.

## Validate event streams with Pydantic

A single resource can now validate mixed event types with a Pydantic discriminated union wrapped in `RootModel`, dispatching each variant to its own table. Define variant models sharing a `Literal` discriminator, then route items with `dlt.mark.with_table_name`. Columns for unmatched items follow the `data_type` contract. This is part of a broader Pydantic v2 rework in #3572.

```py
from typing import ClassVar, Literal, Union
from typing_extensions import Annotated
from pydantic import BaseModel, Field, RootModel
import dlt
from dlt.common.libs.pydantic import DltConfig

class EventBase(BaseModel):
    kind: str
    id: int

class ClickEvent(EventBase):
    kind: Literal["click"]
    element_id: str

class PurchaseEvent(EventBase):
    kind: Literal["purchase"]
    amount: float

EventUnion = Annotated[Union[ClickEvent, PurchaseEvent], Field(discriminator="kind")]

class Event(RootModel[EventUnion]):
    dlt_config: ClassVar[DltConfig] = {"is_authoritative_model": True}

table_map = {"click": "click_events", "purchase": "purchase_events"}

@dlt.resource(name="events", columns=Event, schema_contract={"data_type": "discard_row"})
def event_stream(events):
    for item in events:
        yield dlt.mark.with_table_name(item, table_map[item["kind"]])
```

## Parallel fetching for dependent REST resources

Dependent resources (transformers) in `rest_api` fetched child data one parent at a time. Set `parallelized` to True on a dependent resource and each parent's child fetch runs concurrently in dlt's thread pool. All pages for one parent are collected in memory before yielding, so expect higher memory use for parents with many child pages. See #3574.

```py
{
    "name": "issue_comments",
    "parallelized": True,
    "endpoint": {
        "path": "issues/{resources.issues.number}/comments",
    },
    "include_from_parent": ["id"],
}
```

## Filter dataset relations by load ID

You can now read only the rows from specific loads. `dataset.load_ids()` lists load IDs and `dataset.latest_load_id()` returns the most recent one. Pass `load_ids` to `dataset.table()`, or call `.from_loads()` on a relation, to filter a table (including nested tables) to those loads. This is experimental. See #3547.

```py
import dlt

dataset = dlt.pipeline("my_pipeline").dataset()

# all load ids for this dataset, oldest first
load_ids = dataset.load_ids()

# read only the rows from the latest load
users = dataset.table("users", load_ids=load_ids[-1:])
df = users.df()

# or filter an existing relation to those loads
recent_users = dataset.table("users").from_loads(load_ids[-1:])
```

## Zero-downtime replace on Snowflake

For the `staging-optimized` replace strategy on Snowflake, you can now swap staging and destination tables atomically with `ALTER TABLE ... SWAP WITH` instead of cloning, avoiding downtime during replacement. Enable it with `enable_atomic_swap`. Each table keeps its own permissions after the swap, and dlt does not drop the old table. See #3540.

```toml
[destination.snowflake]
enable_atomic_swap = true
```

## LLM-friendly docs with `llms.txt`

The docs site now publishes an `llms.txt` index and a Markdown version of every page, with a View Markdown badge on each page. This makes it easier to feed dlt documentation to LLM agents and coding assistants. See #3635.
