# Release highlights: 1.22

## Breaking changes

- **Pydantic v1 support removed.** dlt now requires Pydantic v2. All Pydantic v1 compatibility code has been removed, so models and any custom validation must use v2 APIs (for example `model_dump` instead of `dict`). See [#3572](https://github.com/dlt-hub/dlt/pull/3572).
- **`data_type` contract now covers type property changes.** The `data_type` schema contract now applies to type property changes (`data_type`, `nullable`, `precision`, `scale`, `timezone`) on existing complete columns, not only to variant columns. Pipelines using `data_type: freeze` that relied on changing nullability or precision on existing columns will now be blocked. See [#3572](https://github.com/dlt-hub/dlt/pull/3572).
- **Compound hints now replace instead of accumulate.** `merge_columns` previously merged additively, which wrongly kept compound hints like `merge_key` and `primary_key`. Redefining these hints on an already extracted resource now replaces the previous configuration instead of accumulating, and direct key hints take precedence over column-level ones. See [#3431](https://github.com/dlt-hub/dlt/pull/3431).

## Validate event streams with Pydantic discriminated unions

A single resource can now validate a stream of mixed event types using a Pydantic `RootModel` over a discriminated union, dispatching each variant to its own table. The new `is_authoritative_model` option in `DltConfig` lets a model's columns bypass `columns` and `data_type` contract checks. This is part of a broader Pydantic v2 rework in [#3572](https://github.com/dlt-hub/dlt/pull/3572).

```py
from typing import ClassVar, Literal, Union
from typing_extensions import Annotated
from pydantic import BaseModel, Field, RootModel
import dlt
from dlt.common.libs.pydantic import DltConfig


class ClickEvent(BaseModel):
    kind: Literal["click"]
    id: int
    element_id: str


class PurchaseEvent(BaseModel):
    kind: Literal["purchase"]
    id: int
    amount: float


EventUnion = Annotated[Union[ClickEvent, PurchaseEvent], Field(discriminator="kind")]


class Event(RootModel[EventUnion]):
    dlt_config: ClassVar[DltConfig] = {"is_authoritative_model": True}


TABLE_MAP = {"click": "click_events", "purchase": "purchase_events"}


@dlt.resource(name="events", columns=Event, schema_contract={"data_type": "discard_row"})
def event_stream():
    events = [
        {"kind": "click", "id": 1, "element_id": "btn"},
        {"kind": "purchase", "id": 2, "amount": 9.99},
    ]
    for item in events:
        yield dlt.mark.with_table_name(item, TABLE_MAP[str(item["kind"])])
```

## Parallel fetching for dependent REST API resources

Dependent resources (transformers) in `rest_api` sources can now set `parallelized: True`, so child requests for many parent items run concurrently in dlt's thread pool instead of one at a time. All pages of child data for a parent item are collected in memory before being yielded, so memory use rises for parents with many child pages. See [#3574](https://github.com/dlt-hub/dlt/pull/3574).

```py
from dlt.sources.rest_api import rest_api_source

source = rest_api_source(
    {
        "client": {"base_url": "https://api.example.com"},
        "resources": [
            "posts",
            {
                "name": "post_comments",
                "parallelized": True,
                "endpoint": {"path": "posts/{resources.posts.id}/comments"},
            },
        ],
    }
)
```

## Zero-downtime replace on Snowflake with atomic swap

For the `staging-optimized` replace strategy, Snowflake can now swap destination and staging tables with `ALTER TABLE ... SWAP WITH` instead of cloning, removing table downtime during replacement. Enable it with the `enable_atomic_swap` option. Each swapped table keeps its existing permissions, and dlt does not drop the old table, which becomes the next load's staging table. See [#3540](https://github.com/dlt-hub/dlt/pull/3540).

```toml
[destination.snowflake]
enable_atomic_swap = true
```

## Filter dataset tables by load ID

You can now read only the rows from specific loads. `dataset.table(name, load_ids=[...])` filters a table to the given load IDs, resolving `_dlt_load_id` through parent and root keys for nested tables. New `dataset.load_ids()` and `dataset.latest_load_id()` helpers list a dataset's loads. This feature is experimental. See [#3547](https://github.com/dlt-hub/dlt/pull/3547).

```py
import dlt

pipeline = dlt.pipeline(pipeline_name="events", destination="duckdb")
dataset = pipeline.dataset()

# list all load ids, then read rows from the latest load only
load_ids = dataset.load_ids()
recent = dataset.table("users", load_ids=load_ids[-1:]).df()
```

## LLM-friendly docs with llms.txt and Markdown pages

The docs site now generates an `llms.txt` index of all pages and a Markdown version of every page, reachable through a new "View Markdown" link. This makes the documentation easier to feed to LLM tools and agents. See [#3635](https://github.com/dlt-hub/dlt/pull/3635).

## Updates in 1.22.1

### Compact `sources.<name>` configuration layout

When a source's section differs from its name, for example after cloning a source, dlt now also accepts a shorter config path that uses just the source name. The full path and the section path still take precedence over it. See [#3664](https://github.com/dlt-hub/dlt/pull/3664).

```toml
# compact layout: just the source name
[sources.my_db.credentials]
password = "..."

# full layout: section plus name, takes precedence
[sources.my_db_module.my_db.credentials]
password = "..."
```

### ClickHouse reads are now consistent by default

dlt now sets `select_sequential_consistency=1` on every ClickHouse connection so SELECT queries see the results of preceding writes, even on ClickHouse Cloud and clusters. Set it to `0` to skip the small metadata check on read-only workloads. See [#3651](https://github.com/dlt-hub/dlt/pull/3651).

```toml
[destination.clickhouse]
select_sequential_consistency = 0
```

### MCP servers default to streamable-http transport

Built-in MCP servers now start with `streamable-http` transport instead of `sse` and serve on the `/mcp` path, so update your client URLs accordingly. Legacy SSE is still available with the `--sse` flag and stdio with `--stdio`. See [#3624](https://github.com/dlt-hub/dlt/pull/3624).

```sh
# default transport is now streamable-http, served on /mcp
dlt pipeline my_pipeline mcp

# opt into the legacy SSE transport
dlt pipeline my_pipeline mcp --sse
```
