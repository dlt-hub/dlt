# Release highlights: 1.22

## Breaking changes

- **Pydantic v1 support removed.** dlt now requires Pydantic v2. All Pydantic v1 compatibility code was removed, so models and code written for Pydantic v1 must be upgraded to v2 before installing this release. See [#3572](https://github.com/dlt-hub/dlt/pull/3572).
- **`data_type` contract now covers type properties.** The `data_type` schema contract now applies to the full data type, including precision, scale, and nullability, not only variant columns. Pipelines using `data_type: freeze` that changed `nullable`, `precision`, or `scale` on existing columns will now be blocked. See [#3572](https://github.com/dlt-hub/dlt/pull/3572).
- **`merge_columns` compound property handling.** `merge_columns` was purely additive, so compound properties like `merge_key`, `primary_key`, `partition`, and `cluster` were replaced instead of merged. It now removes compound properties that should be removed, changing how repeated hint updates resolve these keys. Its signature also changed. See [#3431](https://github.com/dlt-hub/dlt/pull/3431).

## Validate event streams with a Pydantic `RootModel`

A single resource can now validate a stream of mixed event types using a Pydantic discriminated union wrapped in a `RootModel`. dlt resolves each item to its variant by the discriminator field, dispatches it to a per-type table, and lets the `data_type` schema contract decide what happens to items that match no variant. This requires Pydantic v2. See [#3572](https://github.com/dlt-hub/dlt/pull/3572).

```py
from typing import ClassVar, Literal, Union
from typing_extensions import Annotated
from pydantic import BaseModel, Field, RootModel
import dlt
from dlt.common.libs.pydantic import DltConfig


class EventBase(BaseModel):
    kind: str
    id: int


class ClickEvent(EventBase):
    kind: Literal["click"]
    element_id: str


class PurchaseEvent(EventBase):
    kind: Literal["purchase"]
    amount: float


EventUnion = Annotated[Union[ClickEvent, PurchaseEvent], Field(discriminator="kind")]


class Event(RootModel[EventUnion]):
    dlt_config: ClassVar[DltConfig] = {"is_authoritative_model": True}


TABLE_MAP = {"click": "click_events", "purchase": "purchase_events"}
events: list[dict] = [
    {"kind": "click", "id": 1, "element_id": "buy-now"},
    {"kind": "purchase", "id": 2, "amount": 9.99},
]


@dlt.resource(name="events", columns=Event, schema_contract={"data_type": "discard_row"})
def event_stream():
    for item in events:
        yield dlt.mark.with_table_name(item, TABLE_MAP[item["kind"]])
```

## Parallel fetching for dependent resources in `rest_api`

Dependent resources (transformers) in the REST API source now accept a `parallelized` flag. Set it on a child resource and its fetches for multiple parent items run concurrently in dlt's thread pool instead of sequentially. Note that each parent's child pages are collected into memory before yielding, which raises memory use for parents with many pages. See [#3574](https://github.com/dlt-hub/dlt/pull/3574).

```py
from dlt.sources.rest_api import RESTAPIConfig, rest_api_source

config: RESTAPIConfig = {
    "client": {"base_url": "https://api.example.com"},
    "resources": [
        "posts",
        {
            "name": "post_comments",
            "parallelized": True,
            "endpoint": {
                "path": "posts/{resources.posts.id}/comments",
            },
        },
    ],
}

source = rest_api_source(config)
```

## Filter dataset tables by load id (experimental)

The dataset API can now restrict a table to specific loads. `dataset.load_ids()` lists the load ids recorded for the dataset, `dataset.latest_load_id()` returns the most recent one, and `dataset.table(name, load_ids=[...])` (or `relation.from_loads([...])`) reads only rows from those loads, joining nested tables back to their root when needed. This is experimental. See [#3547](https://github.com/dlt-hub/dlt/pull/3547).

```py
import dlt

pipeline = dlt.pipeline(pipeline_name="crm", destination="duckdb")
dataset = pipeline.dataset()

# all load ids recorded for this dataset (experimental)
load_ids = dataset.load_ids()

# read `users` restricted to the most recent load
recent = dataset.table("users", load_ids=load_ids[-1:])
df = recent.df()
```

## Zero-downtime replace on Snowflake with atomic swap

For the `staging-optimized` replace strategy on Snowflake, you can enable `enable_atomic_swap` so destination and staging tables are exchanged with `ALTER TABLE ... SWAP WITH` instead of being cloned. This avoids table downtime during replacement and preserves each table's permissions. dlt does not drop staging tables, so the old production table becomes the next load's staging table. See [#3540](https://github.com/dlt-hub/dlt/pull/3540).

```toml
[destination.snowflake]
enable_atomic_swap = true
```
