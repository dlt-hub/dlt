# Release highlights: 1.25

## New `lance` destination

Load data into the Lance columnar format on local disk or `s3`, `az`, and `gs`, with optional vector embeddings generated through LanceDB. It uses a Lance Directory Namespace catalog and supports branching, complementing the existing `lancedb` destination that targets LanceDB Cloud. Install with `pip install "dlt[lance]"` ([#3810](https://github.com/dlt-hub/dlt/pull/3810)).

```py
import dlt
from dlt.destinations.adapters import lance_adapter

movies = [{"id": 1, "title": "Blade Runner", "year": 1982}]

pipeline = dlt.pipeline(destination="lance", dataset_name="movies_db")

# optionally embed selected columns as vectors
pipeline.run(lance_adapter(movies, embed=["title"]), table_name="movies")
```

## Datasets can span every schema a pipeline loads

A pipeline that loads several sources now exposes all of their schemas through one `pipeline.dataset()`, so tables from every source are queryable together. This is a new default and is breaking: pass `schema=pipeline.default_schema_name` to restore the single-schema view. Same-named tables across schemas have their columns merged and rows combined ([#3770](https://github.com/dlt-hub/dlt/pull/3770)).

```py
import dlt

pipeline = dlt.pipeline(destination="duckdb", dataset_name="shop")
# after pipeline.run([...]) loads several sources into one dataset:

# dataset() now spans every schema the pipeline loaded
dataset = pipeline.dataset()

# restore the previous single-schema view
default_only = pipeline.dataset(schema=pipeline.default_schema_name)

# load history is tracked per schema
orders_loads = dataset.load_ids(schema_name="orders")
```

## Progress and load metrics survive restarts

Load metrics are now persisted, so they survive a process restart and a resumed load. Normalize reports live per-table row counts through update files, and every load job records the follow-up jobs it spawns, so the full job graph is saved into the pipeline trace. This closes the long-standing [#853](https://github.com/dlt-hub/dlt/issues/853) ([#3768](https://github.com/dlt-hub/dlt/pull/3768)).

## AWS default credential chains are preserved

AWS credentials now keep botocore's default provider chain (IAM roles, profiles, and environment) and resolve lazily instead of copying static keys, so default credentials work across S3-based destinations such as filesystem, Redshift, and Snowflake. DuckDB reads S3 through the `credential_chain` provider, and STS session-token generation is now scoped to Databricks staging only ([#3798](https://github.com/dlt-hub/dlt/pull/3798)).

## REST API child resources no longer lose pages

Dependent (child) resources in the REST API source now receive their own paginator copy for each parent item. Previously a shared paginator's state could be corrupted as dlt interleaved requests across parent pages, which stopped child pagination early and silently dropped records ([#3779](https://github.com/dlt-hub/dlt/pull/3779)).
